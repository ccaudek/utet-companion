Il Capitolo 13 introduce il controllo predittivo a priori come strumento concettuale: tradurre le assunzioni sui parametri in dati osservabili, per giudicarle sulla scala su cui abbiamo intuizioni. Questa appendice mostra come si esegue quel controllo in Stan, e raccoglie in coda alcune indicazioni pratiche sulla scelta dei prior.

ConsiglioDomanda chiave

I prior che abbiamo scelto generano dati che hanno senso nel contesto del problema, o producono scenari che sappiamo non poter accadere?

K.1 L’idioma: un modello senza verosimiglianza

Un controllo predittivo a priori si ottiene in tre passi: si estraggono \(S\) valori dei parametri dalle rispettive distribuzioni a priori; per ciascuno si generano dati simulati; si confronta la distribuzione dei dati simulati con ciò che si sa del fenomeno.

In Stan questo si realizza scrivendo un programma privo di verosimiglianza: il blocco model contiene solo i prior, e il blocco generated quantities produce le repliche con le funzioni _rng(). Senza dati osservati a vincolarlo, il campionatore esplora semplicemente la distribuzione a priori.

Un accorgimento rende il programma molto più utile: mettere gli iperparametri dei prior nel blocco data invece che scriverli nel codice. Così lo stesso modello, compilato una volta sola, può essere eseguito con specificazioni diverse e confrontato.

K.2 Caso 1: modello normale

Assumiamo \(y_i \sim \mathcal{N}(\mu, \sigma)\), dove \(y\) è un punteggio su scala 0–100.

Mostra/Nascondi codice
gauss_prior_stan <- "
data {
  int<lower=1> N;
  real mu_loc;
  real<lower=0> mu_scale;
  real<lower=0> sigma_rate;
}

parameters {
  real mu;
  real<lower=0> sigma;
}

model {
  // Solo prior: nessuna verosimiglianza
  mu ~ normal(mu_loc, mu_scale);
  sigma ~ exponential(sigma_rate);
}

generated quantities {
  vector[N] y_rep;
  for (i in 1:N) {
    y_rep[i] = normal_rng(mu, sigma);
  }
}
"

mod_gauss <- cmdstan_model(write_stan_file(gauss_prior_stan))

Eseguiamo lo stesso modello due volte. Nello scenario A i prior sono molto diffusi; nello scenario B sono debolmente informativi e calibrati sulla scala del punteggio.

Mostra/Nascondi codice
simula_prior <- function(dati) {
  mod_gauss$sample(
    data = dati, chains = 2, iter_warmup = 500,
    iter_sampling = 1000, seed = 123, refresh = 0
  )$draws("y_rep") |>
    as_draws_matrix() |>
    as.vector()
}

y_A <- simula_prior(list(N = 50, mu_loc = 50, mu_scale = 50, sigma_rate = 1 / 20))
y_B <- simula_prior(list(N = 50, mu_loc = 50, mu_scale = 10, sigma_rate = 1 / 10))
Mostra/Nascondi codice
bind_rows(
  tibble(y = y_A, scenario = "A: prior molto diffusi"),
  tibble(y = y_B, scenario = "B: prior debolmente informativi")
) |>
  ggplot(aes(x = y, fill = scenario)) +
  geom_density(alpha = 0.5, adjust = 1.5) +
  geom_vline(xintercept = c(0, 100), linetype = "dashed", linewidth = 0.4) +
  coord_cartesian(xlim = c(-150, 250)) +
  labs(
    x = "Punteggio simulato",
    y = "Densità",
    fill = NULL
  ) +
  theme(legend.position = "bottom")

Le linee tratteggiate delimitano l’intervallo possibile. Lo scenario A assegna probabilità non trascurabile a punteggi negativi e superiori a 100, cioè a valori che sappiamo impossibili: è un’incoerenza logica, non una questione di gusto. Lo scenario B lascia ampia variabilità entro la scala.

L’obiettivo dei prior non è costringere i dati entro un intervallo predefinito, ma evitare che il modello ritenga probabile ciò che il ricercatore sa impossibile.

K.3 Caso 2: regressione lineare

Con \(y = \alpha + \beta x + \varepsilon\) e predittore standardizzato, i prior si interpretano in unità di deviazione standard: un \(\beta \sim \mathcal{N}(0,1)\) rende plausibili effetti moderati e rari quelli superiori a tre deviazioni standard.

Mostra/Nascondi codice
linear_prior_stan <- "
data {
  int<lower=1> N;
  vector[N] x;
  real<lower=0> coef_scale;
  real<lower=0> sigma_rate;
}

parameters {
  real alpha;
  real beta;
  real<lower=0> sigma;
}

model {
  alpha ~ normal(0, coef_scale);
  beta ~ normal(0, coef_scale);
  sigma ~ exponential(sigma_rate);
}

generated quantities {
  vector[N] y_rep;
  for (i in 1:N) {
    y_rep[i] = normal_rng(alpha + beta * x[i], sigma);
  }
}
"

mod_lin <- cmdstan_model(write_stan_file(linear_prior_stan))
Mostra/Nascondi codice
x_grid <- seq(-2, 2, length.out = 40)

adatta_lineare <- function(coef_scale, sigma_rate) {
  mod_lin$sample(
    data = list(
      N = length(x_grid), x = x_grid,
      coef_scale = coef_scale, sigma_rate = sigma_rate
    ),
    chains = 2, iter_warmup = 500, iter_sampling = 1000,
    seed = 123, refresh = 0
  )
}

fit_lin_C <- adatta_lineare(coef_scale = 10, sigma_rate = 1 / 5)
fit_lin_D <- adatta_lineare(coef_scale = 1, sigma_rate = 0.5)

La rappresentazione più informativa non è la distribuzione di \(y\), ma l’insieme delle rette implicite nei prior: mostra direttamente quali relazioni il modello ritiene possibili prima di vedere i dati.

Mostra/Nascondi codice
rette <- function(fit, etichetta, n = 100) {
  draws <- as_draws_df(fit$draws(c("alpha", "beta")))[1:n, ]
  tidyr::expand_grid(draw = 1:n, x = x_grid) |>
    mutate(
      y = draws$alpha[draw] + draws$beta[draw] * x,
      scenario = etichetta
    )
}

bind_rows(
  rette(fit_lin_C, "C: prior larghi (scala 10)"),
  rette(fit_lin_D, "D: prior debolmente informativi (scala 1)")
) |>
  ggplot(aes(x = x, y = y, group = draw)) +
  geom_line(alpha = 0.12, linewidth = 0.4) +
  facet_wrap(~ scenario) +
  coord_cartesian(ylim = c(-20, 20)) +
  labs(x = "x (standardizzato)", y = "y")

K.4 Caso 3: regressione logistica

Qui la scala rende la scelta dei prior meno intuitiva. I parametri agiscono sul logit, e una differenza di due o tre unità sul logit corrisponde al passaggio da una probabilità di circa 0.1 a circa 0.9: un prior che sembra moderato sui coefficienti può implicare quasi-certezza sulle probabilità.

Mostra/Nascondi codice
logistic_prior_stan <- "
data {
  int<lower=1> N;
  vector[N] x;
  real<lower=0> coef_scale;
}

parameters {
  real alpha;
  real beta;
}

model {
  alpha ~ normal(0, coef_scale);
  beta ~ normal(0, coef_scale);
}

generated quantities {
  vector[N] p;
  for (i in 1:N) {
    p[i] = inv_logit(alpha + beta * x[i]);
  }
}
"

mod_log <- cmdstan_model(write_stan_file(logistic_prior_stan))
Mostra/Nascondi codice
set.seed(42)
x_log <- rnorm(100)

probabilita_implicite <- function(coef_scale, etichetta) {
  mod_log$sample(
    data = list(N = length(x_log), x = x_log, coef_scale = coef_scale),
    chains = 2, iter_warmup = 500, iter_sampling = 1000,
    seed = 123, refresh = 0
  )$draws("p") |>
    as_draws_matrix() |>
    as.vector() |>
    (\(v) tibble(p = v, scenario = etichetta))()
}

p_E <- probabilita_implicite(2.5, "E: prior larghi (SD = 2.5)")
p_F <- probabilita_implicite(1.0, "F: prior moderati (SD = 1)")
Mostra/Nascondi codice
bind_rows(p_E, p_F) |>
  ggplot(aes(x = p, fill = scenario)) +
  geom_density(alpha = 0.5) +
  labs(x = "P(y = 1 | x)", y = "Densità", fill = NULL) +
  theme(legend.position = "bottom")
AvvisoSulla scala logit i prior larghi non sono neutrali

Prior ampi in una regressione logistica equivalgono ad assumere, prima di vedere i dati, che siano probabili risposte quasi certe. È un’assunzione forte, e quasi sempre incoerente con la variabilità dei fenomeni psicologici.

K.5 Linee guida pratiche

Lavorare sulla scala appropriata. Standardizzare i predittori quando possibile: un prior \(\mathcal{N}(0,1)\) su \(\beta\) ha allora un’interpretazione diretta in deviazioni standard dell’esito.

Coefficienti.

Prior Interpretazione
\(\mathcal{N}(0, 0.5)\) effetti piccoli molto probabili
\(\mathcal{N}(0, 1)\) effetti moderati probabili
\(\mathcal{N}(0, 2)\) effetti grandi possibili

Intercetta. Con esiti continui, centrare \(y\) rende \(\alpha\) interpretabile come valore medio. Con esiti binari, \(\mathcal{N}(0, 1.5)\) implica una probabilità di base fra circa 0.05 e 0.95.

Dispersione. Usare distribuzioni positive — half-normal, esponenziale, gamma — con il parametro di scala calibrato sulla variabilità attesa del fenomeno.

Scale non lineari. Su logit e log, non giudicare mai i prior sulla scala trasformata: convertire in probabilità o in tassi prima di decidere se siano ragionevoli. È esattamente ciò che il Caso 3 rende visibile.

Documentare. Annotare quali prior sono stati considerati, perché sono stati modificati e quali controlli sono stati eseguiti. È materiale che serve al revisore quanto a chi rifà l’analisi.

Riflessioni conclusive

Il controllo predittivo a priori è un esercizio di coerenza logica, e si esegue prima di raccogliere i dati: verifica che il modello non ritenga probabile ciò che sappiamo impossibile. In Stan si realizza con un programma senza verosimiglianza, e parametrizzare i prior nel blocco data permette di confrontare specificazioni alternative senza ricompilare.

Un insieme di prior è ben specificato quando non esclude valori teoricamente plausibili, non assegna probabilità apprezzabile a scenari che contraddicono ciò che si sa del fenomeno, ed esprime l’incertezza effettiva prima della raccolta dei dati.

Il quadro si completa dopo l’osservazione, con i controlli predittivi a posteriori (Appendice L).
